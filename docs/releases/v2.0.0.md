Hey all! Sorry for the apparent log spam I hadn't noticed. I've gone over this intergration a lot of times in the past few days and I think I've fixed all the bugs I didn't know existed! Maybe? 😆

**Breaking Changes**
Searches are narrower so the integration stays stable. Groups, helpers, and `.storage` files are no longer checked. Repairs now cover automations, scripts, scenes, dashboards, and merged `configuration.yaml` (packages, includes, and themes). Auto-Replace is limited to UI-stored automations, scripts, scenes, and storage dashboards; packages, themes, YAML dashboards, and blueprint-backed UI items stay manual.

**Fixes**
- Find scene entity members, keep scene settings when both old and new ids are already present, and skip Auto-Replace in that case
- Stop writing package automations, scripts, or scenes into the UI yaml files, and edit UI yaml / dashboards through documented files instead of private Home Assistant internals
- Back up UI yaml with `.pre-lost-entity-finder` before Auto-Replace, and restore if the file changed or the edit is unsafe; fall back to file scans when Home Assistant cannot merge `configuration.yaml`
- Quiet template-scan log noise, keep going when one scanner fails, and keep prior hits for failed scopes
- Run one scan at a time, cancel pending work on unload, avoid duplicate startup scans, and rescan only the changed area after automation, script, scene, or dashboard updates
- Keep repairs stable: Fix later and find-references stay open until you choose, Auto-Replace stays open when work is unfinished or failed, Ignore All clears empty repairs, and cards are not rewritten or shared across different entity ids
- Track rename chains to the final entity id, remember renames when a scan finds nothing (including disabled automations), drop the oldest ignore when the list is full, and only forget a finished rename after a full successful empty scan
- List every dashboard view that uses an entity, warn when dashboards cannot be read, and treat YAML dashboards as manual edits
